# T1046: Network Service Discovery

## Overview

This lab demonstrate the detection of network service discovery
activity against a Windows endpoint using Nmap from a Kali Linux
attacker machine.

The activity was monitored using Sysmon and collected through
Winlogbeat into the Elastic Stack.

---

## Lab Environment

| Component | Details |
|---|---|
| Attacker | Kali Linux |
| Attacker IP | `192.168.0.107` |
| Target | Windows |
| Target IP | `192.168.0.104` |
| SIEM | Elastic Stack |
| Sysmon | Enabled |
| Telemetry | Sysmon Event ID 3 |

---

## MITRE ATT&CK

**Tactic:** Discovery

**Technique:** T1046 — Network Service Discovery

**Objective:** Identify network services and ports exposed by
the target system.

---

## Attack Simulation

The reconnaissance activity was performed from the Kali Linux
machine against the Windows endpoint.

### Command

```bash
nmap -sT -p 1-1000 192.168.0.104
````

---

## Expected Telemetry

The expected telemetry for this activity was:

**Sysmon Event ID 3 : Network Connection**

Relevant fields:
- `SourceIp`
- `SourcePort`
- `DestinationIp`
- `DestinationPort`
- `Protocol`
- `Image
- `UtcTime`
---

## Observed Telemetry

The Windows endpoint generated Sysmon Event ID 3 events.
Example:

```text
SourceIp:          192.168.0.107
DestinationIp:     192.168.0.104
DestinationPort:   8080
Protocol:          tcp
Event ID:          3
```

The source IP `192.168.0.107` corresponds to the Kali Linux  
machine performing the reconnaissance.

---

## ELK Pipeline

The telemetry followed this pipeline:

```text
Kali Linux
    |
    | Nmap
    v
Windows Endpoint
    |
    | Sysmon Event ID 3
    v
Winlogbeat
    |
    v
Elasticsearch
    |
    v
Kibana
```

---

## Kibana Investigation

The Event ID 3 events were searched in Kibana using:
```text
event.code: "3"
```
To focus on the Windows endpoint:
```text
event.code: "3" AND destination.ip: "192.168.0.104"
```

The investigation focused on:
- Source IP
- Destination IP
- Destination port
- Number of connections
- Connection frequency
- Timestamp
---

## Detection Logic

A single network connection is not necessarily suspicious.

The stronger indicator is:

> A single source IP contacting a large number of different  
> destination ports on the same host within a short period.

Example:

```text
Source: 192.168.0.107
        |
        +----> 192.168.0.104:21
        +----> 192.168.0.104:22
        +----> 192.168.0.104:80
        +----> 192.168.0.104:135
        +----> 192.168.0.104:445
        +----> 192.168.0.104:3389
```

This behavior is consistent with network service discovery.

The visualization used:

- Y-axis: Count of events
    
- Breakdown: `source.ip`
    
- Filter: Sysmon Event ID 3
    

The reconnaissance activity produced an observable increase in

## Analysis

The reconnaissance activity was successfully observed from the  
Windows endpoint.

The source IP `192.168.0.107` generated multiple network  
connections toward `192.168.0.104`.

The important detection signal was not simply the existence of  
Event ID 3, but the pattern of multiple connections to different  
destination ports from the same source.

---

## Detection Result

**Status:** Detected
**Telemetry:** Sysmon Event ID 3
**Attacker:** `192.168.0.107`
**Target:** `192.168.0.104`
**MITRE ATT&CK:** T1046 — Network Service Discovery

---

## Lessons Learned

- Sysmon Event ID 3 provides useful network connection telemetry.
    
- Network connections need to be analyzed as a pattern rather than  
    individually.
    
- A high number of connections to different ports can indicate  
    reconnaissance.
    
- The source IP can be used to identify the system performing the  
    scanning.
    
- Kibana can be used to visualize the activity and investigate the  
    timeline.
    
- Detection should focus on attacker behavior rather than simply  
    detecting the use of Nmap.
